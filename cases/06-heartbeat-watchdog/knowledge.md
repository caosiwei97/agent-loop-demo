# SSE 心跳 + 超时检测

## 核心概念

有一种比 529 更让人头疼的故障：**连接没有报错，也没有断开，但不再推送数据了。** 用户看到 AI 输出到一半停住，界面显示"正在生成"，但等多久都不会有新内容。

这不是 bug，这是 TCP 的"半开（Half-Open）"状态。用户网络抖动（WiFi 切换、进出电梯），TCP 连接已失效但浏览器不知道。`reader.read()` 一直挂起，try-catch 捕获不到任何错误——**因为没有错误发生，只是在"等"。**

## 关键要点

- 服务端心跳：定期发 SSE 注释帧（`: heartbeat\n\n`），不会触发客户端事件
- 客户端超时检测：定期检查 `lastDataAt`，超时则判定连接失效
- **心跳间隔（15s）必须显著小于超时阈值（30s）**，确保正常情况不会误判
- **整个请求生命周期都需要心跳**——不只是等待模型加载时
- 检测到断开后需要**对账**：服务端持久化的数据是 source of truth

## 代码解析

本案例模拟了三个场景：

1. **正常运行**：数据 + 心跳持续到达，检测器不触发
2. **服务器停止发送**：心跳和数据都停止，检测器在 1.5s 后检测到沉默
3. **恢复 + 对账**：检测到断开后重新连接，确认已收到的数据

```javascript
// 服务端心跳
const heartbeat = setInterval(() => {
  res.write(': heartbeat\n\n');
}, 15_000);

// 客户端超时检测
const timer = setInterval(() => {
  if (Date.now() - lastDataAt > TIMEOUT) {
    reader.cancel(); // 超时则断开
  }
}, 5_000);
```
