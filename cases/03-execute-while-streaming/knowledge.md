# 边说边执行

## 核心概念

生产级 Agent 和 demo 级 Agent 之间最大的性能差距之一：**工具块一完成就立刻开始执行，不等整条消息说完。**

假设模型在一次回复里要做三件事：输出文字、调用 Read A、调用 Read B。在"边说边执行"模式下，Read A 一完成就开始执行，此时模型可能还在生成 Read B 的参数——工具执行和后续工具调用的生成在时间上**重叠**（pipelining）。

一个需要读 5 个文件的任务，感知延迟可能减少 **30-50%**。

## 关键要点

- 最简单的做法是等模型整条消息说完再依次执行工具——逻辑简单但太慢
- 生产级做法：工具块一完成就立即执行，与后续生成在时间上重叠
- 不是所有工具都能并行——有些工具之间有依赖关系（先读文件才能改文件）
- `streamText` + `maxSteps` 实现自动多轮 Agent Loop

## 代码解析

本案例使用 `createMultiTurnModel` 模拟多轮交互。第 1 轮模型发起 3 个并发的 `read_file` 调用，第 2 轮拿到工具结果后输出总结：

```javascript
const result = streamText({
  model,
  tools: allTools,
  prompt: '帮我看看项目的文件结构',
  maxSteps: 5, // 允许最多 5 轮自动循环
});
```

观察时间戳可以发现：工具执行和下一轮工具调用的生成在时间上重叠——这就是"边说边执行"。

## 延伸思考

- 如果你的 Agent 一次性生成了 5 个工具调用，其中 3 个互相独立、2 个有依赖，你怎么调度才能让体验最快？
- 模型还在流式输出时，客户端怎么知道一个工具调用已经"完整"了？判断依据是什么？
