# 哈希指纹检测

## 核心概念

Agent 出问题最常见的方式之一是**死循环**——反复调用同一个工具，做同样的事。它看起来在正常工作（每次都返回了正常结果），不仔细看根本发现不了在原地踏步。

怎么判断两次工具调用是否相同？直觉是比工具名 + 参数。但参数可能很大（整个文件内容），逐字比较太慢。OpenClaw 的做法是**哈希指纹**：

```
指纹 = SHA256(工具名 + 稳定序列化(参数)) 的前 12 位
```

## 关键要点

- **稳定序列化**是关键坑：`{a:1, b:2}` 和 `{b:2, a:1}` 逻辑等价但 `JSON.stringify` 可能不同
- 解决方案：先用 `Object.keys(params).sort()` 排序，再序列化
- **调用指纹相同 + 结果指纹相同 = 无进展 = 死循环**
- **调用指纹相同 + 结果指纹不同 = 有进展 = 合法轮询**
- 指纹只有 12 个字符，O(1) 比较，滑动窗口保留最近 30 次调用

## 代码解析

本案例实现了完整的指纹计算函数：

```javascript
function fingerprint(name, params) {
  const stable = JSON.stringify(params, Object.keys(params || {}).sort());
  return createHash('sha256').update(name + stable).digest('hex').slice(0, 12);
}
```

演示了四个场景：
1. 相同工具 + 相同参数 → 相同指纹 ✓
2. 相同工具 + 不同参数 → 不同指纹 ✓
3. 键的顺序不影响结果（稳定序列化） ✓
4. 模拟死循环检测：`read_file` 同参数同结果被标记为无进展

## 延伸思考

- 打个比方：你打电话给客服 10 次，每次都是"正在处理中"——这是死循环。如果每次得到不同进展信息——这是正常跟进。如何用代码区分这两种情况？
- 为什么只取 SHA256 前 12 位？碰撞概率够低吗？
