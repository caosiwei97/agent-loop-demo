# Token 预算控制

## 核心概念

死循环检测管的是工具层面的重复，但还有一种"作死"不涉及重复工具调用——**模型无限续写**。Claude Code 的做法是给 Agent 设一个**输出 Token 预算**，然后做两件事：90% 时注入 nudge 消息，以及检测递减回报。

## 关键要点

- **90% nudge**：到达预算 90% 时注入"已完成 Token 目标的 X%。继续工作——不要总结。"
- 为什么是 90% 不是 100%？模型不能精确控制输出长度，提前 10% 给缓冲区收尾
- 为什么说"不要总结"？模型收到"快到限制了"的信号后**本能反应就是开始总结**——如果任务还没完成，总结反而浪费 Token
- **递减回报检测**：累计输出 > 5000 Token 后，连续两轮每轮 < 500 Token → 判定为递减回报，停止
- 费用：200 轮失控 × 每轮 1000 Token 输出 + 10-20 倍输入 Token = **$50-100 一次失控**

## 代码解析

本案例模拟了 Token 预算追踪：

```javascript
// 90% nudge
if (!nudgeInjected && ratio >= 0.90) {
  const nudge = `已完成 Token 目标的 ${pct}%。继续工作——不要总结。`;
  messages.push({ role: 'user', content: nudge });
}

// 递减回报
if (totalOutput > 5000 && outputThisTurn < 500) {
  lowStreak++;
  if (lowStreak >= 2) break; // 连续两次递减
}
```

续写过程示例：
```
续写第 1 次: +3000 Token → 正常
续写第 2 次: +2500 Token → 正常
续写第 3 次: +400 Token  → 增量很小
续写第 4 次: +300 Token  → 连续两次递减，停止
```

## 延伸思考

- 输入 Token 才是费用大头（每轮都要带完整上下文），为什么预算控制主要关注输出 Token？
- 如果一个合法的长任务确实需要很多 Token（比如重构一个大文件），nudge 消息会不会干扰它？如何区分"有效工作"和"无效兜圈"？
